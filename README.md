# 🚦 TrafficIQ — Event-Driven Traffic Intelligence for Bengaluru

**Predict how long a road stays blocked → grade congestion (Level 1–4) → automatically
plan barricades, officers, cooldown and diversions — built on 8,157 real Bengaluru
traffic-event records.**

Most traffic AI projects *detect* congestion. Ours goes one step further: it **predicts the
impact and tells the police exactly what to do** — where to barricade, how many officers to
place, where to divert traffic, and for how long to hold incoming flow. It is a
**decision-support system**, not just a dashboard.

---

## ✨ Key Features

| # | Feature | What it does |
|---|---------|--------------|
| 1 | **Block-Time Predictor** | ML estimates how many hours a road will stay blocked |
| 2 | **Congestion Level (1–4)** | Grades severity: 🟢 Minor → 🟡 Building up → 🟠 Serious → 🔴 Critical |
| 3 | **Economic Impact (₹)** | Converts congestion into vehicle-hours lost and rupees |
| 4 | **Barricade & Officer Planner** | Recommends *where* to barricade and *how many* officers, to **distribute** congestion instead of just blocking it |
| 5 | **Cooldown + Diversion** | Suggests a cooldown period and the **calmest nearby zones** to divert traffic toward |
| 6 | **Live City Heatmap** | Interactive map of disruption hotspots = priority enforcement zones |
| 7 | **Explainable AI** | Every recommendation comes with a plain-English "why" |
| 8 | **One-Click Scenarios** | Concert / Procession / VIP movement / Truck breakdown presets for instant demo |

## 🧠 How It Works

```
  EVENT (cause, road, zone, time, closure)
        │
        ▼
  [Model A] Block-time  ──►  [Model B] Congestion Level 1–4
        │                          │
        ▼                          ▼
  Economic impact (₹)        Action Engine
                              ├─ Barricade points + officers
                              ├─ Cooldown period
                              └─ Divert to calmest zones
```

- **Model A** – LightGBM regressor → predicts block duration (hours)
- **Model B** – LightGBM classifier → predicts congestion level. Its prediction is
  **stacked**: Model A's predicted duration is fed in as a feature, lifting accuracy to
  **83.3% (5-fold cross-validated)**
- **Action Engine** – rule-based, fully explainable; "calm zone" ranking is learned from
  the data (zones with the fewest / shortest recent disruptions = best diversion targets)

## 📊 Dataset

Real anonymized Bengaluru traffic-event log (Nov 2023 – Apr 2024), **8,157 events** after
cleaning, including planned events, processions, VIP movement, breakdowns, water-logging,
accidents and more — with location, time, corridor, zone, road-closure and priority.
File: `data/events.csv`.

## ⚙️ Setup (one time)

**Prerequisites:** Python 3.10+ and Node.js 18+

```bash
# 1. install Python packages
pip install -r requirements.txt

# 2. build the clean dataset + train the models
python src/data_prep.py
python src/models.py
```

This creates `data/events_clean.csv` and the trained models in `models/`.

## ▶️ How to Run

You have **two ways** to run the app. The **React app is the main UI**; the Streamlit app
is a simple single-command alternative.

### Option A — React + FastAPI (recommended, main UI)

Open **two terminals**.

**Terminal 1 — backend API** (start this first):
```bash
cd traffic-system
python -m uvicorn api.server:app --port 8000
```

**Terminal 2 — frontend**:
```bash
cd traffic-system/web
npm install        # first time only
npm run dev
```

Now open **http://localhost:5173** in your browser.

> ⚠️ Start the backend (Terminal 1) **before** the frontend, so the UI can load data.

### Option B — Streamlit (single command, alternative UI)

```bash
cd traffic-system
streamlit run app/main.py
```

Then open **http://localhost:8501** in your browser.

## 🎮 How to Use (Demo Flow)

1. Go to the **Simulator** tab.
2. Click a **scenario button** (e.g. *Concert / Public Event*) — the system instantly
   predicts the congestion level, economic impact, and full action plan.
3. Or **fine-tune** the event (cause, road, zone, hour, road-closure) and click
   **Predict & Plan**.
4. Open **City Heatmap** to see disruption hotspots; filter by level.
5. Open **Insights & Model** for model accuracy and city-wide trends.

## 📈 Model Performance

| Model | Metric | Score |
|-------|--------|-------|
| Congestion Level (classifier) | Accuracy (5-fold CV) | **83.3%** |
| Congestion Level (classifier) | F1 (macro) | 0.69 |
| Block-time (regressor) | MAE | ~2.8 hours |

> Note: block-time is reported as an **estimate** — many records lack a precise clearance
> time, so the level prediction is the stronger signal. The dataset is an *event log*, not a
> live speed feed, so the system is **near-real-time and event-driven**, not second-by-second.

## 🏆 Why This Matters

On-street incidents and events choke Bengaluru's corridors, and enforcement today is
reactive and experience-driven. This system turns a raw event log into **actionable
decisions** — quantifying impact in rupees and producing a concrete barricade/officer/
diversion plan — so enforcement can be **targeted, proactive, and measurable**.
